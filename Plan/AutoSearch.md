**AutoSearch: System Design Specification for AI Assistant**

## **1. Project Overview & Objective**

We are upgrading an existing RL-based Search Agent (based on Search-R1 architecture) to AutoSearch.
The core innovation is the "Decoupled Dual-Channel Architecture":

1. **Channel 1 (Internal):** Parametric Memory Retrieval `<recall>` -> `<memory>`. Low cost, used for static knowledge & boundary checks.
2. **Channel 2 (External):** Tool Use `<search>` -> `<observation>`. High cost, used for long-tail/obscure info (Training: Local Wiki; Inference: Google API).

**Goal:** Modify the inference logic, prompt templates, and reward functions to support this dual-channel mechanism for high performance on QA benchmarks (NQ, HotpotQA).

## ---

**2. The Interaction Protocol (XML Definition)**

We enforce a strict XML-based action space.

| Component | Tag Pair | Origin | Description | Cost Model (RL) |
| --- | --- | --- | --- | --- |
| **Reasoning** | `<think>`...`</think>` | Model | Chain-of-thought planning & reflection. | 0 |
| **Action A** | `<recall>`query`</recall>` | Model | **Internal Retrieval.** Used for common facts. | **0.0 (Free)** |
| **Feedback A** | `<memory>`content`</memory>` | System | **SFT:** Generated by GPT-4 (Simulated). <br>

<br>**RL:** Placeholder or "No record" signal. | N/A |
| **Action B** | `<search>`query`</search>` | Model | **External Retrieval.** Used for obscure details. | **Penalty (-0.1)** |
| **Feedback B** | `<observation>`content`</observation>` | System | **Training:** Retrieved from Local Wiki. <br>

<br>**Demo:** Retrieved from Google API. | N/A |
| **Output** | `<answer>`content`</answer>` | Model | Final response. **MUST be Short Entity.** | N/A |

```python
Please answer the user's question step-by-step.

**Core Protocol & Action Space:**
1. **Reasoning (`<think>`):** - ALWAYS start with `<think>` to analyze the question difficulty.

   - *Syntax:* `<recall>keywords</recall>`
   - *Feedback:* `<memory>...</memory>`

3. **External Search (`<search>`):** - **SECONDARY:** Use ONLY if the question is obscure, specific (dates, numbers), or if internal memory fails.
   - *Syntax:* `<search>keywords</search>`
   - *Feedback:* `<observation>...</observation>`

4. **Termination (`<answer>`):**
   - **CRITICAL:** The content inside `<answer>...</answer>` MUST be a **SHORT ENTITY** or **EXACT PHRASE** (e.g., "Paris", "1976", "$10.50"). 
   - DO NOT write complete sentences.

**Trap Handling:**
- If `<recall>` returns `<memory>No record</memory>`, you MUST refuse to answer (e.g., `<answer>N/A</answer>`).
"""

```

### **B. Inference Logic (Python Regex Parsing)**

We need to modify the execution loop to handle the new tags.

Python

```python
import re

def parse_and_execute_step(model_output, env_mode="train"):
    """
    Parses model output for actions.
    env_mode: 'train' (Local Wiki) or 'demo' (Google API)
    """
    
    # 1. Check for External Search (High Cost)
    search_match = re.search(r"<search>(.*?)</search>", model_output, re.DOTALL)
    if search_match:
        query = search_match.group(1).strip()
        
        if env_mode == "train":
            # Call Local Vector DB (Pyserini/Faiss)
            search_results = local_wiki_tool(query)
        else:
            # Call Google Search API
            search_results = google_search_tool(query)
            
        return f"<observation>{search_results}</observation>"

    # 2. Check for Internal Recall (Low Cost)
    recall_match = re.search(r"<recall>(.*?)</recall>", model_output, re.DOTALL)
    if recall_match:
        query = recall_match.group(1).strip()
        
        # NOTE: For SFT, this feedback is already in the dataset.
        # For Inference/RL: We return a placeholder signal.
        # The Model is expected to generate the actual memory content 
        # based on its weights, or we return a standard ACK.
        
        return "<memory>Internal Memory Access: Active.</memory>" 

    return None # No action

```

### **C. Reward Function Design (RL Stage)**

Python

```python
def compute_reward(trajectory, ground_truth, q_type="normal"):
    reward = 0.0
    
    # 1. Base Accuracy (Exact Match)
    prediction = extract_answer(trajectory)
    if exact_match_score(prediction, ground_truth):
        reward += 1.0
    else:
        reward -= 1.0 # Penalize wrong answers heavily

    # 2. Cost Penalty (Budget Awareness)
    num_searches = len(re.findall(r"<search>", trajectory))
    reward -= (num_searches * 0.1) # Search is expensive
    
    # Recall is Free
    # num_recalls = ... (No penalty)

    # 3. Pivot/Trap Bonus
    if q_type == "trap":
        if prediction in ["N/A", "Does not exist", "Refuse"]:
            reward += 1.0
        # Check if it tried to verify before refusing
        if "<recall>" in trajectory and "No record" in trajectory:
            reward += 0.5 

    return reward

```
