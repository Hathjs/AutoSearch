**AutoSearch: System Design Specification for AI Assistant**

## **1. Project Overview & Objective**

We are upgrading an existing RL-based Search Agent (based on Search-R1 architecture) to AutoSearch.
The core innovation is the **"Decoupled Dual-Channel Architecture"**:

1. **Channel 1 (Internal):** Parametric Memory Retrieval `<recall>` -> `<memory>`. Low cost (0.0), used for static knowledge & boundary checks.
2. **Channel 2 (External):** Tool Use `<search>` -> `<information>`. High cost (-0.1 penalty), used for long-tail/obscure info (Training: Local Wiki; Inference: Google API).

**Key Innovation: Decoupling Reasoning and Knowledge Recall**

- **Previous (Search-R1)**: `<think>` mixed logical reasoning with knowledge recall, leading to Sycophancy issues.
- **Now (AutoSearch V2)**: 
  - `<think>`: Pure logical reasoning only
  - `<recall>`: Dedicated tool for knowledge recall
  - This separation allows RL to distinguish between "recall errors" and "reasoning errors"

**Goal:** Modify the inference logic, prompt templates, and reward functions to support this dual-channel mechanism for high performance on QA benchmarks (NQ, HotpotQA).

**2. The Interaction Protocol (XML Definition)**

We enforce a strict XML-based action space.

| Component | Tag Pair | Origin | Description | Cost Model (RL) |
| --- | --- | --- | --- | --- |
| **Reasoning** | `<think>`...`</think>` | Model | Chain-of-thought planning & reflection. | 0 |
| **Action A** | `<recall>`query`</recall>` | Model | **Internal Retrieval.** Used for common facts. | **0.0 (Free)** |
| **Feedback A** | `<memory>`content`</memory>` | System/Model | **SFT:** Generated by GPT-4 (Simulated). <br>

<br>**Inference:** Generated by recall tool (guided prompt). <br>

<br>**RL Training:** Placeholder signal (model generates based on SFT). <br>

<br>**RL Validation:** Generated by recall tool (for testing). | N/A |
| **Action B** | `<search>`query`</search>` | Model | **External Retrieval.** Used for obscure details. | **Penalty (-0.1)** |
| **Feedback B** | `<information>`content`</information>` | System | **Training:** Retrieved from Local Wiki. <br>

<br>**Inference:** Retrieved from Google API or Local Retrieval Server. | N/A |
| **Output** | `<answer>`content`</answer>` | Model | Final response. **MUST be Short Entity.** | N/A |

```python
while True:
    # 1. Model generates response
    output = model.generate(prompt, stopping_criteria=[</search>, </recall>, </answer>])
    
    # 2. Parse actions
    search_match = re.search(r"<search>(.*?)</search>", output, re.DOTALL)
    recall_match = re.search(r"<recall>(.*?)</recall>", output, re.DOTALL)
    answer_match = re.search(r"<answer>(.*?)</answer>", output, re.DOTALL)
    
    # 3. Execute actions
    if answer_match:
        break  # Final answer
    elif search_match:
        query = search_match.group(1).strip()
        results = search_api(query)  # External search
        prompt += output + f"\n\n<information>{results}</information>\n\n"
    elif recall_match:
        query = recall_match.group(1).strip()
        memory = recall_internal_knowledge(query, model, tokenizer)  # Internal recall
        prompt += output + f"\n\n{memory}\n\n"
```

#### **B.3 Design Philosophy**

1. **Recall is a Tool Call**: Like `<search>`, `<recall>` is a tool invocation that triggers a specialized process.
2. **Guided Recall**: The recall tool uses a specialized prompt to guide the model to recall knowledge, not to learn new knowledge.
3. **Mode-Dependent Behavior**:
   - **SFT Training**: Memory content is in the dataset (GPT-4 generated)
   - **Inference/Evaluation**: Call recall tool to guide model recall
   - **RL Training**: Use placeholder (model generates based on SFT training)
   - **RL Validation**: Call recall tool to test model capability

### **C. Reward Function Design (RL Stage)**

Python

```python
def compute_reward(trajectory, ground_truth, q_type="normal"):
    reward = 0.0
    
    # 1. Base Accuracy (Exact Match)
    prediction = extract_answer(trajectory)
    if exact_match_score(prediction, ground_truth):
        reward += 1.0
    else:
        reward -= 1.0 # Penalize wrong answers heavily

    # 2. Cost Penalty (Budget Awareness)
    num_searches = len(re.findall(r"<search>", trajectory))
    reward -= (num_searches * 0.1) # Search is expensive
    
    # Recall is Free
    # num_recalls = ... (No penalty)

    # 3. Pivot/Trap Bonus
    if q_type == "trap":
        if prediction in ["N/A", "Does not exist", "Refuse"]:
            reward += 1.0
        # Check if it tried to verify before refusing
        if "<recall>" in trajectory and "No record" in trajectory:
            reward += 0.5 

    return reward

```
